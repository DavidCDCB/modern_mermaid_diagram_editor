# Mermaid ER + ELK routing research — 2026-10-19

Scope: Official-source review only; no source edits. Workspace declares `mermaid: ^11.12.1`; pnpm lock resolves `11.12.1` (package.json and pnpm-lock.yaml). User reports local node_modules is `11.17.2`; not independently checked here.

## Integration by Mermaid version
- Mermaid `11.12.1` ships ELK separately: `@mermaid-js/layout-elk` README (`https://raw.githubusercontent.com/mermaid-js/mermaid/mermaid%4011.12.1/packages/mermaid-layout-elk/README.md`) says install it, import default `elkLayouts`, call `mermaid.registerLayoutLoaders(elkLayouts)`. `layouts.ts` maps name `elk` to algorithm `elk.layered`; source: `https://raw.githubusercontent.com/mermaid-js/mermaid/mermaid%4011.12.1/packages/mermaid-layout-elk/src/layouts.ts`.
- v11.12.1 package metadata says `@mermaid-js/layout-elk@0.2.0`, runtime dependencies `d3 ^7.9.0`, `elkjs ^0.9.3`, peer `mermaid ^11.0.2`; source: `https://raw.githubusercontent.com/mermaid-js/mermaid/mermaid%4011.12.1/packages/mermaid-layout-elk/package.json`.
- Mermaid `11.17.2` still has external ELK plugin and same registration API; README: `https://raw.githubusercontent.com/mermaid-js/mermaid/mermaid%4011.17.2/packages/mermaid-layout-elk/README.md`. Plugin is `@mermaid-js/layout-elk@0.2.3`, same `d3`/`elkjs` runtime dependencies and Mermaid peer range; source: `https://raw.githubusercontent.com/mermaid-js/mermaid/mermaid%4011.17.2/packages/mermaid-layout-elk/package.json`.
- Do not conflate this with Mermaid v12: official layouts docs say ELK became bundled/default in v12.0.0; until then install/register the plugin. `https://mermaid.js.org/config/layouts.html`.
- Common syntax: diagram frontmatter `---\nconfig:\n  layout: elk\n---` or `mermaid.initialize({ layout: 'elk' })`; docs say layout can be selected in YAML or initialization: v11.12.1 `https://raw.githubusercontent.com/mermaid-js/mermaid/mermaid%4011.12.1/packages/mermaid/src/docs/config/layouts.md`.

## ER integration and routing evidence
- ER unified renderer in both tags reads global `layout`, passes `getRegisteredLayoutAlgorithm(layout)` into shared renderer; it transfers ER `nodeSpacing` and `rankSpacing` to flowchart spacing config. Sources: v11.12.1 `https://raw.githubusercontent.com/mermaid-js/mermaid/mermaid%4011.12.1/packages/mermaid/src/diagrams/er/erRenderer-unified.ts`; v11.17.2 `https://raw.githubusercontent.com/mermaid-js/mermaid/mermaid%4011.17.2/packages/mermaid/src/diagrams/er/erRenderer-unified.ts`.
- ER config exposes `layoutDirection`, `nodeSpacing`, `rankSpacing`, not `elk.edgeRouting`; root `elk` config exposes a finite set (mergeEdges, placement, cycle/model order), not `edgeRouting`. Sources: v11.12.1 `config.type.ts` and v11.17.2 `config.type.ts` at the same raw GitHub paths.
- ELK plugin `elk` alias is `elk.layered`; ELK Layered official reference says it computes node coordinates and edge bend points and its `Edge Routing` default is `ORTHOGONAL`: `https://eclipse.dev/elk/reference/algorithms/org-eclipse-elk-layered.html`. Generic option is `org.eclipse.elk.edgeRouting`, values `UNDEFINED`, `POLYLINE`, `ORTHOGONAL`, `SPLINES`: `https://eclipse.dev/elk/reference/options/org-eclipse-elk-edgeRouting.html`.
- Mermaid's adapter does not set `elk.edgeRouting` from config; it lets `elk.layered` defaults apply. Its `elk.algorithm` option is chosen internally by the registered layout alias, not a documented Mermaid `elk.algorithm` config field. v11.12.1 adapter source: `https://raw.githubusercontent.com/mermaid-js/mermaid/mermaid%4011.12.1/packages/mermaid-layout-elk/src/render.ts`; v11.17.2 adapter source: `https://raw.githubusercontent.com/mermaid-js/mermaid/mermaid%4011.17.2/packages/mermaid-layout-elk/src/render.ts`.
- Both adapters consume ELK `edge.sections` including `startPoint`, `bendPoints`, `endPoint` and turn them into Mermaid edge points. Thus ELK's orthogonal bend geometry is used; it is not merely diagonal segments generated by replacing a curve.
- Important visible-path version difference: plugin changelog `0.2.1` says it changed ELK edge rendering to rounded right-angle segments rather than inheriting global `basis`, fixing curved-looking edges; `0.2.1` targets Mermaid `11.13.0`, so v11.12.1's plugin `0.2.0` predates that fix. By v11.17.2/plugin `0.2.3`, adapter explicitly sets `layoutEdge.curve = 'rounded'` after copying bend points. Changelog: `https://raw.githubusercontent.com/mermaid-js/mermaid/mermaid%4011.17.2/packages/mermaid-layout-elk/CHANGELOG.md`; source adapter above.
- Conclusion: for 11.17.2, `layout: elk` plus a version-matched `@mermaid-js/layout-elk@0.2.3` is the evidence-backed route to globally laid out ER entities and routed right-angle paths with rounded joins. For 11.12.1, `@mermaid-js/layout-elk@0.2.0` performs ELK layout and transfers bend points, but its old curve handling can render curved-looking lines; no guarantee of the approved sharp elbow style. `elk.edgeRouting: ORTHOGONAL` cannot be relied on as a Mermaid config override in either version, since the field is not exposed/passed through.
- Layout is global (`elk.layered` sees graph nodes/edges and computes positions/bend points), but exact resemblance, spacing, crossings, and perfect non-overlap are not guaranteed. ER `nodeSpacing`/`rankSpacing` knobs exist; visual validation against the target image remains necessary.
