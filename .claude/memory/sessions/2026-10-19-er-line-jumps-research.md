# Mermaid ER line-jump research — 2026-10-19

Scope: Official-source and published-bundle comparison for this workspace's Mermaid 11.12.1 + `@mermaid-js/layout-elk` 0.2.3; no project edits.

- Workspace manifests: `package.json` pins layout-elk 0.2.3 and declares Mermaid `^11.12.1`; `pnpm-lock.yaml` resolves Mermaid 11.12.1. `package-lock.json` separately resolves Mermaid 11.17.2 (line 8188), so package managers disagree.
- `@mermaid-js/layout-elk@0.2.3` published core entry loads chunk `render-O7CIS3YK.mjs`; that actual bundle's `createCommonLayoutRenderer` options are `prepareLayout`, `runLayoutCore`, and `paintOptions`, without `afterPaint` / line hops. Exact CDN source: https://cdn.jsdelivr.net/npm/@mermaid-js/layout-elk@0.2.3/dist/chunks/mermaid-layout-elk.core/render-O7CIS3YK.mjs . Its source-equivalent in Mermaid 11.17.2 `packages/mermaid-layout-elk/src/render.ts` likewise lacks the hook.
- The 0.2.3 package changelog identifies its dependency update as Mermaid 11.17.0 and does not list line hops. Feature is PR #8152 / commit `1246a55`, merged after the 11.17.2 line; it adds the ELK afterPaint hook: https://github.com/mermaid-js/mermaid/pull/8152 . Changelog in 12.2.0 source describes hops on by default, `elk.lineHops: false` to disable and `'gap'` for gaps: https://raw.githubusercontent.com/mermaid-js/mermaid/mermaid%4012.2.0/packages/mermaid-layout-elk/CHANGELOG.md .
- Mermaid 11.17.2 already has generic helper `packages/mermaid/src/rendering-util/rendering-elements/lineJump.ts`; it detects segment intersections, edits the yielding path to an SVG arc or gap, and skips unsupported smoothing curves. Existing caller is swimlanes `packages/mermaid/src/rendering-util/layout-algorithms/swimlanes/adjustLayout.ts`, controlled by `swimlane.lineHops`. Exact sources: https://raw.githubusercontent.com/mermaid-js/mermaid/mermaid%4011.17.2/packages/mermaid/src/rendering-util/rendering-elements/lineJump.ts and https://raw.githubusercontent.com/mermaid-js/mermaid/mermaid%4011.17.2/packages/mermaid/src/rendering-util/layout-algorithms/swimlanes/adjustLayout.ts . Thus helper wasn't conceptually swimlane-only, but before PR #8152 its production consumer was swimlanes.
- Mermaid 11.12.1 source has no `lineJump.ts` at the later path (official raw path returned 404); its ELK adapter and `config.type.ts` have neither line-hop integration nor `elk.lineHops`. ER config only exposes layout direction, entity sizes/padding, spacing, stroke/fill/font. Official config: https://raw.githubusercontent.com/mermaid-js/mermaid/mermaid%4011.12.1/packages/mermaid/src/config.type.ts . ER unified renderer resolves the configured registered layout and calls shared `render`: https://raw.githubusercontent.com/mermaid-js/mermaid/mermaid%4011.12.1/packages/mermaid/src/diagrams/er/erRenderer-unified.ts .
- Mermaid 12.2.0 carries `lineJump.ts`, `elk/lineHops.ts`, and `elk/render.ts` registers `afterPaint: applyElkLineJumps`; ER unified renderer still delegates to registered layout. Therefore a line-hop pass can apply to ER when its active layout is that ELK implementation, despite ER not having its own lineHops option. Set `elk.lineHops` globally / in config (not `er.lineHops`). Sources: https://raw.githubusercontent.com/mermaid-js/mermaid/mermaid%4012.2.0/packages/mermaid/src/rendering-util/layout-algorithms/elk/render.ts and https://raw.githubusercontent.com/mermaid-js/mermaid/mermaid%4012.2.0/packages/mermaid/src/diagrams/er/erRenderer-unified.ts .
- Same mechanism applies by integration, not globally to every Mermaid type: default ELK renderer hook applies to diagrams using that ELK renderer and having renderable edge paths; swimlanes separately call helper with `swimlane.lineHops`; other layouts/types do not gain hops just by existing.
- Post-render feasibility: helper uses the SVG paths' `data-id` and `data-points` plus edge curve/marker metadata, then rewrites `d`. Mermaid 11.12.1 `edges.js` writes `data-id`/`data-points`, so a custom SVG postprocessor is technically feasible after SVG render. Caveats: helper itself is absent/unexported there, must port/adapt it; run after layout and final path emission but before export/snapshot; need correct layer/path selection and edge metadata; only real segment-interior crossings; endpoint touches rejected; smoothed curves skipped; short hops near bends/crowded crossings can be omitted; original curve corner rounding is lost on hopped segment. Source data points: https://raw.githubusercontent.com/mermaid-js/mermaid/mermaid%4011.12.1/packages/mermaid/src/rendering-util/rendering-elements/edges.js .
- Published upgrade lead: npm latest lookup (2026-10-19) reports Mermaid 12.2.0 and `@mermaid-js/layout-elk` 1.0.1; ELK package 1.0.1 peer range is Mermaid `^12.0.0`, while 0.2.3 peer supports Mermaid 11. Recommendation for native behavior is compatible Mermaid 12.x + matching layout package (or Mermaid 12 normal build where ELK is bundled); do not expect the current 11.12.1 + 0.2.3 combination to provide ER hops merely by setting config.
