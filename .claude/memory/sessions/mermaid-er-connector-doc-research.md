# Mermaid ER connector research

- Scope: ER relationship line geometry / `curve: linear`, project range `^11.12.1`; no source files changed.
- Exact Mermaid release: official `mermaid@11.12.1` release is commit `762b44cf33878e7cc3300514c63dfa3f108fd9cb` (https://github.com/mermaid-js/mermaid/releases/tag/mermaid%4011.12.1).
- In that source, `MermaidConfig` exposes `flowchart?: FlowchartDiagramConfig` and `er?: ErDiagramConfig`; only `FlowchartDiagramConfig` declares `curve`, documented as rendering curves for flowcharts and accepting `linear`. `ErDiagramConfig` has no `curve` field (https://github.com/mermaid-js/mermaid/blob/762b44cf33878e7cc3300514c63dfa3f108fd9cb/packages/mermaid/src/config.type.ts).
- ER v11.12.1 renderer imports `curveBasis` and calls `.curve(curveBasis)` when generating relationship paths; ER DB data also assigns `curve: 'basis'` (https://github.com/mermaid-js/mermaid/blob/762b44cf33878e7cc3300514c63dfa3f108fd9cb/packages/mermaid/src/diagrams/er/erRenderer.js; https://github.com/mermaid-js/mermaid/blob/762b44cf33878e7cc3300514c63dfa3f108fd9cb/packages/mermaid/src/diagrams/er/erDb.ts).
- Thus `flowchart.curve: 'linear'` is not an ER relationship setting. ER's `--` vs `..` relationship operator selects identifying solid vs non-identifying dashed style, not line geometry (https://github.com/mermaid-js/mermaid/blob/762b44cf33878e7cc3300514c63dfa3f108fd9cb/packages/mermaid/src/docs/syntax/entityRelationshipDiagram.md).
- Flowchart syntax: preferred frontmatter `---\nconfig:\n  flowchart:\n    curve: linear\n---`; API `mermaid.initialize({ flowchart: { curve: 'linear' } })`; init directive also documented but deprecated in favor of frontmatter. Sources: https://github.com/mermaid-js/mermaid/blob/762b44cf33878e7cc3300514c63dfa3f108fd9cb/packages/mermaid/src/docs/syntax/flowchart.md and https://github.com/mermaid-js/mermaid/blob/762b44cf33878e7cc3300514c63dfa3f108fd9cb/packages/mermaid/src/docs/config/directives.md.
- Workspace lockfile resolves Mermaid to `11.17.2`, despite declared range `^11.12.1` (package-lock.json line 8187); version-specific conclusion was checked against official 11.12.1 release source as requested.
